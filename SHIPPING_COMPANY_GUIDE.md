# Shipping Company Integration Guide

## Overview

The shipping company logic enables seamless integration with delivery carriers (transporteurs). This system handles the complete lifecycle of shipments from creation to delivery, including automatic status updates from carriers.

## Workflow

### 1. Connect a Carrier

**Endpoint:** `POST /api/companies/{id}/connect`

**Authentication:** Required (Admin only)

**Request:**
```json
{
  "api_key": "your_carrier_api_key",
  "api_secret": "optional_api_secret",
  "username": "optional_username",
  "password": "optional_password"
}
```

**Response:**
```json
{
  "message": "Transporteur connecté avec succès.",
  "company": {
    "id": 1,
    "name": "Marjane",
    "is_active": true,
    "api_key": "encrypted_key",
    "webhook_enabled": false
  }
}
```

**Key Points:**
- Credentials are encrypted before storage
- Company becomes active after successful connection
- Only admins can connect carriers

### 2. Enable Orders Updates Subscription

After connecting a carrier, you must enable automatic status updates. This registers a webhook with the carrier.

**Endpoint:** `POST /api/companies/{id}/enable-updates`

**Authentication:** Required (Admin only)

**Response:**
```json
{
  "message": "Mise à jour des commandes activée avec succès.",
  "company": {
    "id": 1,
    "webhook_enabled": true,
    "webhook_registered_at": "2026-05-20T15:50:00Z"
  },
  "webhook_result": {
    "webhook_id": "wh_123456",
    "status": "active"
  }
}
```

**What it does:**
- Registers a webhook URL with the carrier: `https://yourdomain.com/api/shipments/webhook/{companyId}`
- Carrier will send status updates to this endpoint
- Status updates are automatically processed and reflected in your system

### 3. Create Parcels for Orders

Once the carrier is connected and updates are enabled, you can create shipments for orders.

**Endpoint:** `POST /api/shipments`

**Authentication:** Required

**Request:**
```json
{
  "order_id": 123,
  "delivery_company_id": 1,
  "recipient_name": "John Doe",
  "recipient_phone": "+212612345678",
  "address": "123 Rue de la Paix",
  "city": "Casablanca",
  "region": "Casablanca-Settat",
  "country": "MA",
  "cod_amount": 599.99,
  "weight": 2.5,
  "dimensions": {
    "length": 30,
    "width": 20,
    "height": 15
  }
}
```

**Response:**
```json
{
  "message": "Colis créé avec succès.",
  "shipment": {
    "id": 456,
    "order_id": 123,
    "delivery_company_id": 1,
    "tracking_number": "TRK123456789",
    "status": "picked_up",
    "recipient_name": "John Doe",
    "recipient_phone": "+212612345678",
    "address": "123 Rue de la Paix",
    "city": "Casablanca",
    "region": "Casablanca-Settat",
    "country": "MA",
    "cod_amount": 599.99,
    "created_at": "2026-05-20T15:50:00Z"
  }
}
```

**Key Points:**
- Order details are used as defaults if not provided
- Tracking number is generated by the carrier
- Shipment status starts as "picked_up" (initial carrier status)
- Multiple shipments can exist per order (different carriers)
- Cannot create duplicate shipments for same order/carrier combination

### 4. Tracking and Automatic Updates

#### Get Current Tracking Information

**Endpoint:** `GET /api/shipments/{id}/tracking`

**Response:**
```json
{
  "shipment_id": 456,
  "tracking_number": "TRK123456789",
  "tracking_info": {
    "status": "in_transit",
    "current_location": "Fes Distribution Center",
    "estimated_delivery": "2026-05-22",
    "events": [
      {
        "date": "2026-05-20T16:00:00Z",
        "status": "picked_up",
        "location": "Casablanca Hub",
        "notes": "Package collected"
      },
      {
        "date": "2026-05-21T08:00:00Z",
        "status": "in_transit",
        "location": "Fes Distribution Center",
        "notes": "In transit to delivery point"
      }
    ]
  }
}
```

#### Webhook: Automatic Status Updates

The carrier sends status updates to: `POST /api/shipments/webhook/{companyId}`

**Webhook Payload Example:**
```json
{
  "tracking_number": "TRK123456789",
  "status": "in_transit",
  "notes": "Package in transit to delivery point",
  "company_id": 1
}
```

**Status Mapping:**
- `collected` → `picked_up`
- `picked_up` → `picked_up`
- `in_transit` → `in_transit`
- `out_for_delivery` → `out_for_delivery`
- `delivered` / `completed` → `delivered`
- `returned` → `returned`
- `failed` / `cancelled` → `failed`

**Automatic Actions:**
- Shipment status is updated
- `shipped_at` timestamp is set when status is "picked_up"
- `delivered_at` timestamp is set when status is "delivered"
- All updates are logged

**Endpoint:** `GET /api/shipments`

**Query Parameters:**

### 6. Cancel a Shipment

**Endpoint:** `DELETE /api/shipments/{id}`

**Response:**
```json
{
  "message": "Colis annulé avec succès.",
  "shipment": {
    "id": 456,
    "status": "failed"
  }
}
```

**Restrictions:**
- Cannot cancel shipments that are "delivered" or "cancelled"
- Sends cancellation request to the carrier API
- Status is set to "failed"

## Shipment Statuses

| Status | Description | Final |
|--------|-------------|-------|
| `pending` | Shipment created, awaiting pickup | No |
| `picked_up` | Picked up by carrier | No |
| `in_transit` | In transit to delivery location | No |
| `out_for_delivery` | Out for delivery today | No |
| `delivered` | Successfully delivered | Yes |
| `returned` | Returned to sender | Yes |
| `failed` | Delivery failed or cancelled | Yes |

## Error Handling

  "message": "Le transporteur n'est pas connecté."
}
```

```

```json

```

**Webhook processing error (500):**
```json

  "message": "Error processing webhook"

```

## Database Schema

### Shipments Table
- `id` - Primary key
- `order_id` - Foreign key to orders
- `delivery_company_id` - Foreign key to delivery_companies
- `tracking_number` - Unique tracking identifier
- `status` - Current shipment status
- `recipient_name`, `recipient_phone`, `address`, `city`, `region`, `country` - Delivery details
- `cod_amount` - Cash on delivery amount
- `delivery_notes` - Additional notes
- `shipped_at` - When shipment was picked up
- `delivered_at` - When shipment was delivered
- `created_at`, `updated_at` - Timestamps

### Delivery Companies Table
- `id` - Primary key
- `name` - Company name
- `phone` - Contact phone
- `api_url` - API endpoint
- `api_key` - Encrypted API credentials
- `credentials` - JSON field for additional credentials
- `is_active` - Connection status
- `webhook_enabled` - Automatic updates enabled
- `webhook_registered_at` - When webhook was registered
- `created_at`, `updated_at` - Timestamps

## Implementation Example

```php
// 1. Connect a carrier
$response = Http::post('/api/companies/1/connect', [
    'api_key' => env('MARJANE_API_KEY'),
]);

// 2. Enable updates
$response = Http::post('/api/companies/1/enable-updates');

// 3. Create shipment
$response = Http::post('/api/shipments', [
    'order_id' => 123,
    'delivery_company_id' => 1,
    'cod_amount' => 599.99,
]);
$trackingNumber = $response->json()['shipment']['tracking_number'];

// 4. Track shipment
$response = Http::get('/api/shipments/456/tracking');

// 5. Get shipment details
$response = Http::get('/api/shipments/456');
```

## Security Considerations

1. **Credential Encryption**: API keys and credentials are encrypted using Laravel's encryption
2. **Authentication**: All endpoints (except webhooks) require authentication
3. **Authorization**: Only admins can connect/manage carriers
4. **Webhook Signature**: Webhooks include optional signature verification
5. **Rate Limiting**: Implement rate limiting on webhook endpoints in production
